# Technical debt register

| Issue | Impact and severity | Components and evidence | Resolution, priority, verification |
| --- | --- | --- | --- |
| Public customer and payment APIs lack end-user identity | Unauthorized business actions are possible; **High** | Gateway and LegacyCommerce route handlers accept requests without user authentication. | Add OIDC/OAuth2 and resource authorization; **P0**. Verify anonymous rejection, customer isolation, and end-to-end token propagation. |
| Internal service tokens are shared secrets | Leakage permits spoofed internal commands; **High** | Orders-to-Legacy and Inventory write adapters use configured headers. | Use workload identity/mTLS with scoped authorization and rotation; **P0**. Verify impersonation denial and rotation without downtime. |
| Legacy execution paths remain | Maintenance cost and residual SQL schema surface; **Medium** | Catalog, Inventory, and Orders legacy code remains behind extracted ownership flags; no complete retirement audit. | Inventory every caller and background writer, finish rollback window, archive historical reads, then remove obsolete execution paths; **P1**. Verify routes, migration history, and data reconciliation before any deletion. |
| No live cluster qualification | Kustomize success cannot prove deployment behavior; **High** | CI renders manifests and builds images but does not run kind ingress or multi-pod workflow. | Add isolated kind smoke with managed test dependencies and gateway replicas; **P1**. Verify health, ingress, restarts, state agreement, and no conflicting writers. |
| Broker poison/error queue recovery not fully exercised | Failed messages can require manual handling; **Medium** | Existing live broker test covers outbox replay and duplicate inbox effect; no bounded poison-event assertion. | Add isolated failure-injection test and replay runbook; **P1**. Verify retry exhaustion, error queue, replay, and one business side effect. |
| Payment uncertainty requires operator decision | Orders can remain pending indefinitely; **Medium** | Saga retains uncertain outcome rather than compensating. | Add explicit reconciliation API and alert/runbook with idempotent provider query; **P1**. Verify provider timeout/restart/duplicate outcomes. |
| Observability stack not exercised end to end | Missing trace or alert rules may go unnoticed; **Medium** | Compose and dashboard configuration parses; no Collector-to-Jaeger/Grafana runtime evidence. | Run isolated telemetry smoke and assert trace/span linkage and metric samples; **P1**. Verify collector outage leaves workflows available. |
| Load behavior is unmeasured | Capacity and P99 remain unknown; **Medium** | No benchmark was executed; bounded k6 scripts are provided. | Run against disposable infrastructure and record throughput, P50/P95/P99, saga latency, and backlog drain; **P1**. Establish thresholds from observed baseline. |
| Stateful recovery is documented but not drilled | Restore time and data loss are unknown; **High** | SQL Server, PostgreSQL, RabbitMQ, and migration authority have no recorded restore exercise. | Run encrypted backup/restore drills and fault-injection exercises in isolated environment; **P0**. Verify identifiers, outbox state, and ownership revision. |

Optional future enhancements: independent Payments and Notifications services, a MassTransit state machine Saga, and Redis-backed read cache. They are not correctness requirements for the current hybrid architecture.
